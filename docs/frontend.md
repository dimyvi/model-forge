# Frontend Model Forge

[К документации проекта](README.md)

Frontend написан на React, TypeScript и Vite. Он показывает датасеты, создаёт эксперименты и получает результаты от Django API.

## Запуск через Docker Compose

Из корня проекта:

```bash
docker compose -f local.docker-compose.yml up -d --build
```

Откройте `http://localhost:5173`. Vite перенаправляет запросы `/api` в контейнер `backend`. Дополнительно запускать frontend на компьютере не нужно.

## Команды без Docker

Нужен Node.js; в Docker и CI используется версия 20. Из папки `frontend`:

```bash
npm ci
npm run dev
```

API должен быть запущен отдельно на `http://127.0.0.1:8000`. Другой адрес можно задать через `VITE_API_PROXY_TARGET` в настройках Vite.

Проверки перед коммитом:

```bash
npm run lint
npm run build
```

Первая команда проверяет ESLint, вторая — TypeScript и сборку. В production React собирается в статические файлы, которые раздаёт Nginx; Vite там не запускается.

## Где искать код

| Путь | Что находится |
| --- | --- |
| `src/App.tsx` | Маршруты страниц |
| `src/pages/` | Страницы датасетов, экспериментов, входа и справки |
| `src/components/` | Общие элементы интерфейса |
| `src/services/` | Запросы к API и типы ответов |
| `src/hooks/` | Загрузка доступных алгоритмов |
| `src/utils/` | Язык, сообщения, тема и форматирование |
| `public/` | Статические файлы |

Клиент в `src/services/api.ts` обращается к `/api` и добавляет `Authorization: Token ...`. В локальном режиме запросы перенаправляет Vite, в Compose production — внешний Nginx. При переносе в Kubernetes маршруты задаст Ingress; одного запуска frontend-контейнера для доступа к API недостаточно.

Форма `/train` создаёт эксперименты классификации. Для регрессии пока используется API. На экране редактирования можно менять целевую колонку и алгоритмы, тип задачи отображается без переключателя.
